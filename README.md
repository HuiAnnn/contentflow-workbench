# ContentFlow · 商品内容工作台

供运营人员整理商品资料、生成文案、审核并发布到本系统商品页的网页工具。界面使用 React 与系统字体，提供完整页面式操作和多组 API 连接管理。

**这个仓库支持下载后在自己电脑运行。** 本地数据保存在本机，不需要 ChatGPT 登录、Cloudflare 账号或原作者的网站权限。调用真实模型时，需要自己配置有效的模型 API Key。

## 第一次运行

准备 Node.js **22.13 或更高版本**（推荐 Node 22），然后下载并解压源码。打开终端，进入包含 `package.json` 的文件夹，依次运行：

```sh
npm ci
npm run setup:local
npm run dev:local
```

打开终端显示的本机网址，默认是 **http://127.0.0.1:5173**。保持终端运行，关闭时按 `Ctrl+C`。

- `npm ci` 按锁文件安装依赖，需要能访问 npm。
- `setup:local` 构建项目、生成本机专用加密密钥，并按顺序初始化本地数据库。重复执行不会重建已初始化的数据库或更换已有密钥。
- `dev:local` 启动完整本地工作台。页面会通过开发环境的本地登录模拟进入固定的本机工作区；不会跳到真实 ChatGPT OAuth。
- 下次打开只需再次运行 `npm run dev:local`。

端口被占用时可以指定另一个端口：

```sh
npm run dev:local -- --port 5180
```

本地启动只监听回环地址，适合自己使用，不是面向公网或局域网的多人登录方案。

## 先跑通一次商品流程

1. 在「新建内容任务」粘贴商品资料，进入字段核对。
2. 补齐商品名称、类目等字段，并确认字段。
3. 在「内容与版本」点击「使用模板示例」，无需模型 Key 即可验证后续流程；也可以配置模型后点击「AI 生成内容」。
4. 选择或编辑内容模块，提交审核，再到「内容审核」审核通过。
5. 商品进入「待发布」，在「发布商品」发布到本系统商品页。
6. 刷新或重启后，商品与发布快照仍保存在本机数据库中。

审核通过后仍需执行发布；导出文件不会代替发布。已发布页面展示最后一次审核发布的快照，后续编辑不会立即改动它。

## 配置 OCR 与文案模型

进入「模型与 API」→「添加连接」：

- 填写连接名称、接口地址、模型 ID 与 Key。
- 不必选择厂商。常规接入使用 **OpenAI Chat Completions 兼容协议 + Bearer API Key**；保留对已有专用 OCR.space 接口的适配。
- 同一个接口、同一个模型的多个 Key 可以每行一个批量粘贴；「加 Key」可以复用已保存的地址和模型。
- OCR 与文案在页面上方分别选择默认连接，保存到列表不会自动启用。
- OCR 必须选择支持图片输入的视觉模型；文本模型不能仅靠勾选用途变成视觉模型。
- 「测试」会调用服务商，可能使用额度。限流、欠费、权限或模型 ID 错误会显示在页面中。

Key 只会发送给该连接配置的服务端地址。不会把一串未知 Key 发送到多家厂商尝试识别，也不进行自动轮换或失败后切换账号。

## 数据和备份

本地运行使用 Cloudflare D1 的本地 SQLite 模拟，不会自动同步原网站数据。

| 位置 | 用途 |
| --- | --- |
| `.wrangler/state/` | 商品、内容版本、操作记录和加密后的 API Key |
| `.dev.vars` | 本地 Worker 的加密密钥 |
| `.env.local` | 与 `.dev.vars` 同步保存的本地加密配置 |
| `drizzle/` | 源码中的数据库迁移文件，不包含你的商品资料 |

备份时先停止服务，再一起备份 `.wrangler/state/`、`.dev.vars` 和 `.env.local`。**只有数据库而丢失加密密钥，将无法解密已保存的 API Key。** 不要把这些运行文件提交到 GitHub，也不要把自己的运行目录直接压缩给朋友。

更新源码后，如增加了迁移文件，停止服务后重新运行 `npm run setup:local`。脚本只操作本地数据库。如果检测到早期手动初始化、没有迁移记录的旧开发数据库，会停止并提示先备份，不会猜测版本或自动删除数据。

## 当前功能边界

- 支持资料粘贴和 JPG / PNG / WebP 图片 OCR；不包含 Excel、PDF、Word 的完整文件解析。
- 文案生成需要能从运行机器访问模型服务；免费模型的额度和速度由服务商决定。
- 本地版本是一个固定用户的独立工作区。界面中的负责人、团队角色与设计交付登记，不等同于完整的多人权限或协同系统。
- 发布目标是本系统商品页，不是淘宝、京东等外部电商平台。
- 示例商品及图片随源码提供，你在原在线工作区中录入的商品和 Key 不会随仓库分享。

## 检查是否运行正常

先启动 `npm run dev:local`，再在另一个终端运行：

```sh
npm run test:local
```

该检查通过本地登录 cookie 验证数据库、API 连接管理、字段确认、模板内容、审核、发布与退出登录。它会增加一条带有「本地验证」名称的测试商品，使用的 API Key 是测试字符串，不会发起真实模型调用。

模型请求和旧数据兼容可单独验证：

```sh
node tests/model-runtime.test.mjs
node tests/connections-runtime.test.mjs
```

这些运行时测试拦截模型请求，不需要真实 Key。仓库包含 GitHub Actions 的安装、构建、数据库初始化和核心流程检查；真实模型连通性仍需在自己的电脑和账户下测试。

## 源码与部署

技术栈：React 19、Vinext / Vite、Cloudflare Workers、D1 / SQLite、Drizzle、Radix / shadcn 组件。

```text
app/                    页面与后端 API
lib/                    商品流程、模型请求和 Key 存储
scripts/setup-local.mjs  本地初始化
scripts/export-github.mjs  生成不含个人运行数据的分享副本
build/                  构建与本地登录适配
```

这不是静态网站，不能直接用 GitHub Pages 托管完整系统。`npm run build` 输出 Worker 构建产物；原有 `npm start` 是开发者调试构建产物的低层命令，不提供本地登录模拟，日常本地使用请运行 `dev:local`。

在线版使用 Sites 的身份分发与 D1 配置。导出的 `.openai/hosting.json` 只保留逻辑绑定，不携带原作者的项目 ID。若要把源码部署到自己的云平台，需要另外配置受信任的登录入口、数据库、服务端密钥与访问权限，不能直接信任公网客户端自填的 `oai-authenticated-user-*` 请求头。

在有 Git 元数据的开发仓库中，可以导出一份干净源码：

```sh
npm run export:github
```

输出到 `releases/contentflow-github/`，不包含 `.git`、原项目 ID、数据库、Key、缓存、`node_modules` 或构建产物。请上传这个目录的内容，不要上传自己的整个开发目录。

数据库迁移命令的行为可参考 [Cloudflare D1 官方说明](https://developers.cloudflare.com/d1/wrangler-commands/#migrations-apply)。本地模拟登录代码随仓库提供，仅在开发服务中运行。第三方代码许可证保留于 `build/` 与 `vendor/`。
